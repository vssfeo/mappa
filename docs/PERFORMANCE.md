# Производительность

Цели 1.0 из [ROADMAP.md](ROADMAP.md), Phase 7: старт ≤ 1,5 с, 60 fps на
1440p, память без утечек за двухчасовую сессию.

## Как измерять

| Команда | Что показывает |
|---|---|
| `make bench-start` | FCP, LCP, готовность канваса карты и длинные задачи в preview-сборке |
| `make bench-ui` | fps при скриптованном панорамировании, 2560×1440, реальный GL |
| `make startup` | время до окна и до WebKit, установившийся PSS релизного бинарника |
| `make bench` / `make bench-large` | скорость хранилища и сборки паков |

`bench-start` и `bench-ui` запускают `vite preview` сами, если порт 4173
свободен; `MAPPA_URL` позволяет указать другой адрес. `startup` требует
X11 или XWayland (`xwininfo`), без него время окна будет `n/a`.

## Замеры 2026-10-25

Ubuntu 24.04, Wayland + XWayland, AMD FirePro W7000 (radeonsi),
2560×1440, dpr 1, тёплый page cache.

| Метрика | До | После |
|---|---|---|
| First contentful paint | 780 мс | 84 мс |
| Largest contentful paint | 780 мс | 552 мс |
| Канвас карты готов | 862 мс | 760 мс |
| Окно на экране | 72 мс | 70 мс |
| Процесс WebKit запущен | 330 мс | 330 мс |
| Панорамирование, 1440p | 60 fps | 60 fps |
| JS heap после пана | 23 / 82 МиБ | 32 / 78 МиБ |
| Суммарный PSS приложения | 325 МиБ | 309 МиБ |
| — процесс `mappa` | 74 МиБ | 75 МиБ |
| — `WebKitWebProcess` | 232 МиБ | 216 МиБ |
| — `WebKitNetworkProcess` | 17 МиБ | 17 МиБ |

Память считается по PSS, а не по сумме RSS: 122 МиБ из RSS процесса `mappa`
приходится на общие страницы библиотек и драйвера, которые нельзя записать
в счёт приложения.

## Что изменено

- Статический boot-экран в `ui/index.html`: тема берётся из сохранённой
  настройки до загрузки бандла, индикатор уважает `prefers-reduced-motion`.
  React заменяет заглушку при монтировании. Дало 780 → 84 мс до FCP:
  раньше первый кадр ждал разбора MapLibre и инициализации карты.
- `ui/scripts/bench-start.mjs` — воспроизводимый замер старта, встроен в
  `npm run bench:start` / `make bench-start`.
- `scripts/measure-startup.sh` — замер реального бинарника (окно, WebKit, PSS).
- В `MapCanvas` уже были `fadeDuration: 0` и отключённое вращение; кэш тайлов
  MapLibre ограничен размером вьюпорта, отдельный лимит не нужен.

## Замеры 2026-10-26 (1.16.0)

Тот же стенд, тёплый page cache; релизный бинарник 1.16.0, 3 прогона.

| Метрика | Тёплый старт | Холодный прокси (`posix_fadvise` на бинарник) |
|---|---|---|
| Окно на экране | 64–73 мс | 63–121 мс |
| WebKit запущен | 296–344 мс | 290–352 мс |

Настоящий `drop_caches` не выполнен: в этой сессии нет root

вытесняет только бинарник; библиотеки и шрифты остаются в кэше, поэтому
цифры — верхняя оценка холодного старта, а не худший случай.

### Leak, 2026-10-26

Команда: `scripts/measure-leak.sh 120 60` (интервал 60 с). Приложение
проработало **104 минуты**, после чего процесс исчез; последние 17
замеров — нули.

| Минута | PSS, МиБ |
|---|---|
| 1 | 332 |
| 30 | 332 |
| 60 | 331 |
| 90 | 332 |
| 103 | 333 |

Рост за 104 минуты: **332 → 333 МиБ (+1 МиБ, 0,3%)** при пороге 10%.
Тренда вверх нет; колебания в пределах 1–2 МиБ.

Полные два часа не подтверждены: процесс завершился около 17:03 без
отчёта о падении (crash reporting выключен по умолчанию), лог пуст, в
системном журнале нет OOM или segfault. Похоже на закрытие окна или
внешний сигнал; для закрытия T5 нужен один непрерывный двухчасовой
прогон.

## Узкие места

- Длинная задача 270–300 мс на инициализацию MapLibre и первого стиля.
  Убирается только ленивой загрузкой карты, но тогда сама карта появляется
  позже — для картографического приложения это ухудшение.
- Чанк MapLibre 1,06 МБ (gzip 288 КБ) грузится сразу; остальное — 567 КБ
  приложения, 211 КБ React, 27 КБ иконок.
- `WebKitWebProcess` — основной потребитель памяти; кэш тайлов и стили
  растут с количеством открытых паков и слоёв.

## Холодный старт и утечки

- `make startup-cold` вытесняет сам бинарник из page cache
  (`posix_fadvise`), библиотеки WebKitGTK/GTK остаются в кэше. В таком
  приближении окно появляется за 65–115 мс, WebKit — за 332–340 мс,
  то есть как при тёплом старте: время определяют библиотеки, а не наш
  бинарник. Полный холодный старт требует `drop_caches` под root и
  остаётся в чек-листе.
- `make leak` снимает PSS приложения и потомков раз в 30 секунд,
  пишет CSV и предупреждает, если рост больше 10%.
- Прогон 2026-10-25, 10 минут, 20 сэмплов: 300 МиБ → 301 МиБ (+0,3%).
  Утечки не видно; двухчасовой прогон ещё не делался.

## Что осталось

- Инструментировать готовность карты внутри приложения: сейчас 760 мс — это
  preview-сборка в Chromium, а не WebKitGTK.
- Повторить старт на холодном page cache (`/proc/sys/vm/drop_caches`).
- Двухчасовой прогон на утечки: PSS до и после, а не только старт.
- Проверить fps на встроенной графике (Intel/AMD iGPU) и на ARM64.
