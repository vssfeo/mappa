# Mappa — статус реализации

**Дата:** 2026-10-24  
**Фаза:** 1.0 release candidate — восемь пунктов готовности закрыты

---

## Сделано

### Ядро

- Rust workspace: `mappa-core`, `mappa-storage`, `mappa-net`, `src-tauri`.
- Web Mercator: `TileCoord`, `TileRange`, TMS, quadkey, parent/children.
- `Bbox`: валидация, объединение, пересечения, центр.
- Каталог провайдеров: YAML, валидация, URL-шаблоны, TMS, `{-y}`,
  rate limit, auth-описание, флаг `offline_allowed`.
- Встроены OSM, OSM Germany, OpenTopoMap, CARTO Dark, USGS Imagery,
  Esri World Imagery и NASA Blue Marble.
- 35 unit-тестов ядра (CRS: round-trip, Web Mercator, СК-42/Пуля,
  произвольный proj4; полигоны: point-in-ring, пересечение тайла,
  нормализация; bounds тайлов).

### Кэш (`mappa-storage`)

- SQLite WAL, `synchronous=NORMAL`, `busy_timeout`, page cache 32 МиБ,
  mmap 128 МиБ; горячие запросы используют `prepare_cached`.
- Ключ: provider + z/x/y + format + variant.
- ETag, Last-Modified, Content-Type, TTL, BLAKE3-хеш.
- Атомарные upsert/remove/clear и счётчики размера/попаданий.
- LRU-вытеснение по `last_used`, лимит диска (по умолчанию 2 ГиБ).
- `Cache Doctor`: `quick_check`, `recount`, `vacuum`, `clear_expired`.
- Чтение/запись из нескольких потоков, тест конкурентных писателей.
- MBTiles 1.3: чтение, потоковая запись, импорт в кэш, TMS↔XYZ.
- PMTiles v3: чтение через mmap, запись, Hilbert-порядок, экспорт района
  с транскодингом; метаданные name/attribution/bounds/zooms.
- Очередь загрузок: jobs, прогресс, статусы, восстановление после
  аварийного завершения.
- 39 unit-тестов хранилища (включая полигонную маску заданий,
  миграции схемы очереди v1/v2 → v3 и курсор возобновления).

### Сеть (`mappa-net`)

- `reqwest` + rustls, gzip/brotli/deflate, proxy, таймауты.
- Per-provider token bucket и семафор конкурентности.
- Retry с экспоненциальным backoff и jitter, `Retry-After`.
- Условные запросы `If-None-Match` / `If-Modified-Since`, обработка 304.
- TTL из `Cache-Control`, `Expires`; учёт `Age`; `no-store`.
- Проверка сигнатур PNG/JPEG/WebP, отсечение HTML-ошибок с кодом 200.
- Детект `x-blocked` (OSM отдаёт 200 + картинку-заглушку):
  ответ не кэшируется и не маскируется под настоящий тайл.
- Auth: header, query, basic; секреты не логируются.
- 20 unit-тестов, включая mock HTTP, retry, rate limit, auth, blocked,
  ограничение тела ответа, `Retry-After` и загрузку текстовых
  документов (GetCapabilities) с заголовками.

### CLI (`mappa-cli`)

- Headless `providers`, `download`, `pack`, `doctor`, `stats`.
- Общий кэш с приложением (`~/.cache/dev.mappa.desktop/tiles.sqlite3`).
- `download`: bbox/zoom, оценка, `--dry-run`, лимит 2 млн тайлов,
  прогресс, rate limit, legal-гейт `offline_allowed`; 12 параллельных
  загрузок с общим token bucket (2438 тайлов Крыма за 218 с).
- `pack`: MBTiles или PMTiles по расширению выходного файла, метаданные
  bbox/zooms/attribution, транскодинг смешанных PNG/JPEG.
- `doctor`: статистика, `quick_check`, `vacuum`.
- Проверено: USGS 1 тайл z14, OSM блокируется, MBTiles и PMTiles по
  6 тайлов (~98 КБ), все тайлы JPEG (PNG сконвертированы), PMTiles v3
  с корректной сигнатурой и Hilbert-порядком.

### Tauri shell

- Tauri 2.12, WebKitGTK 4.1, нативное окно 1440×900 (HiDPI 2880×1800).
- Команды: провайдеры, статистика/очистка кэша, лимит, `read_tile`.
- Raw IPC (`tauri::ipc::Response`) отдаёт байты без base64.
- MapLibre `mappa://tiles/...` → Rust-кэш → сеть.
- Stale-while-revalidate: просроченный тайл отдаётся сразу и
  перепроверяется в фоне; при ошибке сети остаётся офлайн-копия.
- Коалесинг одинаковых запросов по ключу тайла.
- Отмена запросов, ставших ненужными при панорамировании: UI шлёт
  `cancel_tile`, Rust дропает HTTP-future и не тратит лимит провайдера.
- Хэндлер тайлов пропускает вытеснение кэша раз в 64 записи и пишет
  `last_used`/счётчики пакетно, а не двумя UPDATE на каждый тайл.
- `MAPPA_LOG=debug` включает подробный лог в release-сборке.
- Очередь: постановка, пауза, продолжение, отмена, удаление,
  авто-возобновление после перезапуска, события прогресса.
- Экспорт MBTiles и PMTiles по завершённой/паузнутой задаче в
  `~/Downloads`, с транскодингом смешанных PNG/JPEG.
- Импорт MBTiles/PMTiles как слоя: реестр паков, чтение тайлов через
  `mappa://pack/...`, восстановление паков после перезапуска.
- Настройки в JSON (`settings.json`): лимит кэша и HTTP-прокси,
  применяются без перезапуска; клиент пересобирается при смене прокси.
- Пользовательские источники XYZ/TMS, WMS GetMap и WMTS:
  `custom-providers.json` (0600), произвольные заголовки/API-ключи,
  scheme XYZ/TMS, `{y}`/`{-y}`, для WMS — `{bbox-epsg-3857}`,
  для WMTS — `{TileMatrix}`/`{TileCol}`/`{TileRow}` или XYZ-токены.
  URL проверяется на абсолютный http(s)-адрес и обязательные
  плейсхолдеры; ошибка показывается под полем и подсвечивает его.
  Кнопка «Из GetCapabilities» скачивает документ нативным клиентом,
  разбирает слои без внешних XML-зависимостей, выбирает Web
  Mercator, формат и шаблон `ResourceURL` (или KVP `GetTile`),
  подставляет зум-диапазон и размер тайла. Пресеты заголовков:
  Bearer, X-Api-Key, Basic. Источник сразу доступен и как слой,
  и в очереди загрузок; записи можно редактировать, встроенные id
  защищены от перезаписи. При смене URL/тайлинга кэш источника
  очищается, чтобы не отдавать старые тайлы.
- Провайдеры с `offline_allowed: false` блокируются в очереди.
- Векторные импорты: бинарный мост (KMZ/SHP/DBF/PRJ), GeoPackage
  читается напрямую через SQLite (WKB + GeoPackage-заголовок, CRS
  через proj4rs), GeoTIFF пишется Rust-модулем без GDAL/libtiff.
- CRS-команды: `crs_presets` и `transform_points` (proj4rs +
  crs-definitions) — пересчёт WGS84 ↔ EPSG/произвольный proj4, без
  сети и внешнего PROJ. Разобранные CRS кэшируются (до 32), поэтому
  обновление координат курсора не парсит proj4 заново.
- `.deb`: `target/release/bundle/deb/Mappa_0.1.0_amd64.deb` (6,21 МиБ).

- React 19 + TypeScript + Vite 8 + MapLibre GL JS.
- Семь подложек (OSM, OSM Germany, CARTO, OpenTopoMap, USGS,
  Esri World Imagery, NASA Blue Marble),
  тёмная/светлая темы.
- Командная палитра `Ctrl+K`, шпаргалка `?`.
- Download sheet: bbox, выделенная область или полигон объекта, зумы,
  оценка, лимит 2 млн тайлов, legal-гейт.
- Полигонная маска: кнопка «Скачать» у полигона в панели «Объекты»;
  очередь считает и качает только тайлы, пересекающие контур (vertex
  inside tile / tile corner inside ring / edge crossings), задание
  хранит полигон в SQLite и переживает перезапуск.
- Рисование прямоугольной области: клавиша `R`, кнопка «Район» на HUD,
  команда палитры, подсветка GeoJSON, `Esc` — отмена; выделение
  используется в загрузке.
- Линейка SAS-стиля: клики по вершинам, расстояние и азимут каждого
  сегмента, сумма; `M`, `Backspace` — убрать точку, `Esc` — очистить.
- Площадь полигона: сферическая площадь, периметр, подпись в центре;
  `Shift+M`.
- Метки: постановка кликом (`P`), перетаскивание, список с
  переименованием, перелёт, удаление, сохранение между запусками;
  при >250 метках — GPU-слой без DOM-подписей. У выбранной точки —
  три одинаковых поля с подсказками при наведении; переключение
  WGS84 градусы/ГМС/UTM/MGRS и плоских СК-42 X/Y/Z (EPSG:284xx,
  зона по долготе или префиксу Y). UTM/MGRS считаются в JS, СК-42 —
  через нативный proj4rs; высота сохраняется в проекте. Иконку можно
  выбрать из набора или загрузить свою (растр масштабируется
  до 64×64 PNG).
- Массовый импорт/экспорт меток: GeoJSON, CSV, GPX, KML; WGS84
  DD/DMS/UTM/MGRS для CSV (UTM-зона автоматически), выбор разделителя
  и колонок CSV, толерантный разбор колонок и DMS, XML-экранирование
  и CDATA.
- Защита импорта: лимит 20 000 меток и длины строк, файл ≤64 МБ.
- Рисование линий и полигонов (`L`, `Shift+L`): клики по вершинам,
  предпросмотр сегмента, Enter/двойной клик — завершить, Backspace —
  убрать точку, Esc — отмена. Цвет, имя, длина/площадь.
- Редактирование (`E`, панель «Объекты»): выбор объекта, перетаскивание
  вершин, добавление/удаление вершины, правый клик по вершине,
  переименование, удаление. Вершины рисуются отдельным GPU-слоем.
- Автосохранение линий/полигонов в проекте (localStorage),
  импорт/экспорт GeoJSON и GPX (WGS84, закрытые кольца). GPX-треки
  импортируются и в «Объекты»; высоты и время каждого `<trkpt>`
  сохраняются в проекте и возвращаются в GPX при экспорте.
- Плеер трека для выбранной линии: play/pause, перемотка, скорость
  ×1–×10, движущийся маркер и пройденное расстояние. Для GPX с
  `ele`/`time` — интерактивный график высоты и скорости по расстоянию,
  набор/сброс высоты, длительность и максимальная скорость.
- GPS/GNSS (`G`, панель «GPS / GNSS»): живая позиция через системную
  геолокацию WebKit/GeoClue, точность, высота, скорость и курс;
  маркер с направлением, круг точности и live-трек на карте, режим
  follow. Запись с паузой, сбросом и сохранением в «Объекты»;
  отбрасываются точки ближе 2 м и с точностью хуже 100 м, неподвижный
  трек получает точку раз в 30 с. Сохранённый трек содержит высоты и
  время, открывается в плеере с графиком и экспортируется в GPX.
  При отказе доступа показывается понятная ошибка; внешний gpsd/NMEA
  остаётся следующим шагом.
- HUD: только иконки с всплывающими подсказками; район, линейка,

- Горячие клавиши привязаны к физическим клавишам и работают в

### Надёжность и производительность (аудит)

- HTTP: потоковое ограничение размера тела (без OOM на ошибочном
  ответе), обрезка `Retry-After` до 30 с, ключ rate bucket включает
  rps/burst, поэтому правка источника применяется сразу.
- Очередь: CAS-переходы статусов (`queued → running`, терминальные
  статусы не перезаписываются), атомарная регистрация отмены до
  старта воркера, пауза/отмена прерывают текущий запрос тайла, а не
  ждут его завершения. `running` — обычный мьютекс, хендл воркера
  публикуется синхронно; снимок списка не воскрешает удалённые задания.
  При возобновлении уже скачанные тайлы проверяются по индексу, без
  чтения блобов; курсор уровня сохраняется в схеме v3, поэтому
  повторный проход не пересчитывает готовые тайлы, а прогресс не
  откатывается назад.
- Кэш: все пишущие транзакции `IMMEDIATE` — нет `SQLITE_BUSY_SNAPSHOT`
  при параллельных загрузках.
- Экспорт паков: атомарная запись через временный файл, при ошибке
  частичный файл удаляется; полигонная маска учитывается и в MBTiles,
  и в PMTiles; прогресс PMTiles считается от общего числа тайлов.
- Пользовательские источники: заголовки сливаются по имени (API-ключ
  не теряется при правке), секреты не возвращаются в WebView, загрузка
  и экспорт используют тот же провайдер, что и просмотр.
- Запись документов, настроек и источников идёт через общий атомарный
  writer: уникальный temp-файл рядом + `fsync` + rename, конкурентные
  записи не теряют данные, обрыв не оставляет обрезанный файл.
  Файловый мост дополнительно ограничен абсолютными путями, allowlist
  расширений, канонизацией и запретом каталогов конфигурации/кэша.
- `make check` сканирует исходники на невидимые символы: zero-width,
  bidi-марки, BOM, нестандартные пробелы, private-use, битый UTF-8,
  non-NFC и смешение латиницы с кириллицей/греческим в идентификаторах.
- MBTiles-тайлы читаются через `spawn_blocking`, паки не блокируют
  async-воркеры; PMTiles-чтения больше не сериализуются общим мьютексом.
- CLI: ошибки записи в кэш считаются failed (а не тихим успехом),
  `JoinSet` ограничен по памяти.
- UI: viewport/курсор вынесены из persisted-store, сериализация и
  запись в localStorage откладываются до затишья (250 мс + flush на
  `pagehide`), persisted-поля восстанавливаются по allowlist, DOM-маркеры
  переиспользуются по id, список меток постраничный, слои поднимаются
  только при структурном изменении, маркеры не перехватывают клики в
  режимах рисования.

## Готовность 1.0

1. Векторные слои входят в `.mappa`, импортированные геометрии
   редактируются вершинами, клик по середине сегмента вставляет
   вершину; правый клик удаляет. Режим `E` объединяет точки, линии
   и полигоны; у точек меняются иконка и цвет, у полигонов — цвет;
   при наведении показывается название объекта. Круг (`O`) строится
   по центру и радиусу и сохраняется как 64-вершинный полигон.
2. Интерфейс RU/EN с сохранением языка; skip-link, `lang`, подписи
   элементов, focus trap и возврат фокуса в диалогах, `aria-live`
   для уведомлений, `prefers-reduced-motion`.
3. Автосохранение проекта в отдельный recovery-слот; манифест пака
   с SHA-256 и Ed25519-подписью, лицензия в метаданных MBTiles/PMTiles.
4. COG с overview-пирамидой, KMZ для векторных слоёв, поля печати PDF.
5. MGRS, координатная сетка на карте, сближение меридианов, масштаб
   сетки, магнитное склонение WMM2025 и круговой контроль CRS.
6. Мультиисточник с резервными провайдерами, проверка и ремонт битых
   тайлов, скорость/ETA очереди, импорт папки XYZ в MBTiles.
   Измеренный маршрут сохраняется в объекты; во время инструментов
   карта панорамируется правой или средней кнопкой.
7. Настоящий git-репозиторий, CI для check/bundle/ARM64, `mappa`
   внутри `.deb`, разделение JS-бандла на чанки.
8. GeoPackage: выбор feature-слоя; SHP: WKT/`prj` с проекциями
   через proj4.

## Известные ограничения

- Векторные PMTiles не поддерживаются; паки только растровые.
- Экспорт паков не показывает прогресс на больших файлах.
- Свои источники: растровые XYZ/TMS, WMS GetMap и WMTS (EPSG:3857).
  WMTS без Web Mercator или с нечисловыми уровнями не добавляется
  автоматически; query-параметр для ключа можно вписать в URL
  или передать заголовком.
- С домашней сети `tile.openstreetmap.org` отдаёт `x-blocked`
  (HTTP 200 + заглушка), CARTO также отдаёт одноцветную заглушку;
  рабочие для проверки — OpenTopoMap и `tile.openstreetmap.de`.
  Поэтому для тестов собран пак из OpenTopoMap.
- Автосохранение `.mappa` идёт в recovery-слот раз в 12 секунд;
  метки и объекты дополнительно живут в localStorage (лимит 20 000).
- Точность пресетов СК-42/МСК зависит от proj4-строки региона;
  нужна полевая проверка на реальных выписках.
- PMTiles не отдаёт точное число тайлов — в UI показывается только
  зум-диапазон.
- Офлайн-очередь намеренно недоступна для OSM/OpenTopoMap/CARTO:
  их условия запрещают bulk pre-fetch. Для офлайна — USGS или
  собственный разрешённый источник.
- USGS отдаёт смесь PNG и JPEG; кэш/MapLibre это переживают,
  а MBTiles-экспорт транскодирует PNG→JPEG (quality 88).
- Полигонная маска скачивает пересекающиеся тайлы; coverage map
  показывает уже закэшированные тайлы, но не прогресс очереди.
- Импорт CSV синхронный; очень большие файлы могут подвесить UI.
- GeoPackage показывает список feature-слоёв, но не растровые тайлы.
- SHP понимает WGS84, Web Mercator, UTM и распространённые
  WKT-проекции; экзотические датумы могут требовать proj4-строку.
- Нет геокодера, 3D и маршрутизации.
- Встроенный YAML-каталог в UI статический; новые источники
  добавляются через «Слои» → «Свои источники» или CLI.
- Прокси только HTTP/HTTPS (без SOCKS).
- `MAPPA_CACHE_LIMIT_MB` при старте переопределяет сохранённый лимит,
  но не записывается в `settings.json`.
- CLI-бинарник называется `mappa-cli` и не входит в `.deb`.
- Браузерная сборка не имеет дискового кэша и очереди.
- JS-бандл разделён на shell, React, иконки и MapLibre; чанк MapLibre
  остаётся ~1,06 МБ и грузится параллельно.
- CI-задачи bundle и ARM64 описаны в workflow; локально проверены
  `make check`, `make deb-check`, `make smoke` и сборка для amd64.
